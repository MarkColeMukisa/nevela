# Nevela web

Flare's Next.js dashboard (from `examples/next-shop` in `MUKE-coder/flare-framework`, MIT, see `LICENSE-flare`) with Laravel behind it. The pages, tables, forms and themes are Flare's. The data and sign-in layer is replaced: this app has no database and no auth library of its own.

## Run it

Start the Laravel app first (`apps/api`, see the root README), then:

```sh
cp .env.example .env.local     # NEVELA_API_URL, default http://127.0.0.1:8000/api
pnpm install
pnpm dev
```

Sign in at `/sign-in` with a user that exists in the Laravel app.

## How it talks to Laravel

| File | What it does |
|---|---|
| `lib/laravel.ts` | The only `fetch` to Laravel. Sends the Sanctum token as a Bearer header from the server. |
| `app/auth-actions.ts` | Sign in (`POST /auth/token`, token kept in an httpOnly cookie) and sign out (`DELETE /auth/token`). |
| `lib/session.ts` | The current user, from `GET /auth/me`. |
| `lib/resource/store.ts` | `laravelStore`: list, get, create, update, replace, delete over Laravel's REST API. Validation errors come back from Laravel and show next to the right field. |
| `lib/dashboard.ts` | What Flare's components import: the store per resource, stats (`GET /{slug}/_stats`), permissions. |
| `proxy.ts` | Sends visitors without a token cookie to `/sign-in`. |

## Generated by Laravel

`php artisan nevela:resource` and `nevela:generate` in `apps/api` write into this app:

- `resources/<name>.resource.ts`: the Flare descriptor. Regenerated between the markers.
- `resources/index.ts`: the registry of every descriptor.
- `app/dashboard/<slug>/…`: list, new, detail and edit pages. Written once, then yours.

## Left out for now

These parts of Flare's app depended on its own database or Better Auth and were removed: sign-up, password reset, two-factor, passkeys, the account pages, saved views, the audit history, the per-day chart, product search, costs and observability pages. File and relation fields are not generated yet (see the roadmap in `apps/docs/src/content/docs/concepts/architecture.md`).

`policies/index.ts` can hide buttons per role, but it is display only. Laravel's policies decide what is allowed.
